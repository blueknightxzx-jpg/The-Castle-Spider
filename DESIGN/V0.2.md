# The Castle Spider — v0.2
## PLAYER — REVISED

### Goal
Create a reusable horizontal player controller with a replaceable character appearance.

### Systems
- Player entity
- Horizontal movement only
- Acceleration/deceleration
- Walking
- Sprinting
- Stamina drain
- Stamina recovery
- Facing direction
- Horizontal world bounds
- Player bounds
- Default character skin
- Replaceable skin architecture
- Player HUD foundation

### Controls
- A / Left Arrow: left
- D / Right Arrow: right
- Shift: sprint
- E: reserved for future interaction

### Explicitly banned player movement
- W
- S
- Up Arrow
- Down Arrow

These inputs do not move the player.

### Character appearance
The starting appearance is a simple neutral Default character.

The Knight is NOT the default player anymore. Knight and other skins are future content and should plug into the same Player controller.

### Design constraints
- Horizontal movement must feel deliberate rather than instant.
- Sprint must have a meaningful tradeoff.
- Stamina must recover predictably.
- Player feet remain aligned to the hallway floor.
- Rendering remains lightweight.
- Appearance must be replaceable without rewriting movement.

### Acceptance criteria
1. Player moves only left/right.
2. Sprint works.
3. Stamina drains and recovers.
4. Player remains inside horizontal world bounds.
5. W/S/up/down never move the player.
6. Default appearance is not a knight.
7. Skin rendering is separated from movement logic.
8. Player state remains available for later animation and interaction.

### Status
Completed, with Structural Amendment 01 applied.
