# The Castle Spider — v0.3
## CASTLE — REVISED

### Goal
Create a large, visually organized side-view castle hallway that can support later interaction and horror systems.

### Systems
- Castle world data
- Connected hallway sections
- Long horizontal traversal
- World-sized camera travel
- Structured architecture grid
- Windows
- Columns
- Door/arch features
- Floor and carpet alignment
- Wall paneling
- Torches / light zones
- North exit marker
- Castle scene
- Player integrated into hallway

### Alignment rules
- Consistent ceiling height
- Consistent floor baseline
- Repeating structural bay width
- Windows centered inside open wall bays
- Columns stay on structural boundaries
- Torches use fixed wall anchors
- Doors/arches never overlap windows or columns
- Decorative elements remain inside their assigned bay
- Player feet share the same floor baseline as the environment

### Design constraints
- The castle must feel deliberately constructed, not randomly decorated.
- Sections may differ through lighting, materials and focal features while sharing the same underlying alignment system.
- The world must be larger than the viewport.
- Camera movement must remain stable.
- Rendering must remain lightweight.
- v0.3 does not implement interaction yet.

### Acceptance criteria
1. Player traverses horizontally through a multi-section castle.
2. W/S/up/down have no movement effect.
3. Camera follows the player.
4. Castle architecture follows a consistent alignment grid.
5. Major decorative objects do not overlap structurally.
6. Player feet align with the hallway floor.
7. Castle data remains separate from rendering.
8. The Default character is used.

### Status
Complete after Structural Amendment 01. Geometry, controls, player floor alignment, and castle composition have been checked.
