# The Castle Spider — v0
## GAME DESIGN LOCK

v0 is a design and architecture phase. Do NOT build the full game yet.

### Objective
Define the game's identity clearly enough that later development has a stable target.

### v0 tasks
1. Lock game identity.
2. Lock design pillars.
3. Define the complete player loop.
4. Establish the story framework.
5. Define the visual direction.
6. Define target controls/platform constraints.
7. Define technical principles.
8. Define what is explicitly OUT of scope for the first playable build.

### Proposed identity
- Genre: 2D side-view survival horror
- Setting: mysterious castle
- Player: knight-like protagonist
- Primary threat: giant spider-like creature
- Platform target: browser
- Hardware priority: low-spec browser devices must remain supported

### Design pillars
- Tension
- Risk
- Uncertainty
- Progression

### Core loop
Explore → listen → detect danger → find safety → hide → survive → continue → discover → escape

### Foundation rules
- Systems must be modular.
- Performance must be considered from the beginning.
- Randomness must remain fair.
- Placeholder content must be replaceable.
- Do not add systems only because they sound cool; every system needs a gameplay purpose.

### v0 acceptance criteria
v0 is complete only when the design document answers:
- What is the player doing most of the time?
- What creates tension?
- What makes the spider distinct?
- What makes the castle worth exploring?
- What does progression change?
- What is the intended art/audio direction?
- What is the minimum playable slice for v0.1?
- What features are postponed?

### Next version
After v0 is completed, v0.1 begins with the technical foundation.
